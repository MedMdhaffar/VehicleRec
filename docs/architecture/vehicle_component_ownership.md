# Vehicle component ownership

Current milestone (2026-11-07): atomic Plate completion observation and pre-mutation
tenant validation are repaired. A separate owned AOF/always Redis profile validates
process restart with exact metadata replay and the same live Engine ledger. The
bounded injected runner reports explicit state and canonical parity. Native
PostgreSQL remains BLOCKED without an explicitly configured disposable target.
See [current results](vehicle_restart_results.md), [operator guide](vehicle_operator_guide.md)
and [v2 contract](vehicle_plate_requests_v2.md). Statements and execution counts
in the earlier stage records below are historical, including their then-current
limitations. This is not a deployed or complete production architecture.

Supervisor-confirmed target, recorded 2026-11-01. Implementation status: scalar in-memory boundaries plus bounded Redis codec/workers. Real native Redis 8.2.11 validation passed all 11 integration methods in two complete runs. Worker-crash recovery is tested; Redis-server restart and power-loss durability are not. PostgreSQL and inference remain disconnected. This is not a deployed architecture.

RTSP/MP4 reading and decoding belong to an Input block before Engine. Engine owns pixels, detection, tracking, association, image quality and every local model invocation. Colour, Plate and Manufacturer are metadata-only domain services. Aggregator owns class consensus, terminal joining and immutable natural DB1 delivery. Redis Streams is the target broker. Only the replaceable DB1 consumer resolves database keys and writes final facts. Supervisor has confirmed Engine's separate PostgreSQL raw execution trace boundary; its physical schema, credentials and retention still need platform contracts. Every boundary carries explicit org_id, which is an identity field and does not establish authorization.

No AI/provider fallback exists anywhere in the target. No SQLite participates in the target. Legacy stores, providers, source and behavior remain preserved during transition. Hybrid scheduling means ordered tracking per camera with bounded independent branches; native/GPU model access is initially serialized.

## Confirmed boundaries and public interfaces

| Component | Owns | Slice implementation |
|---|---|---|
| Input | RTSP/MP4 source connection, read, decode and paired receipt immediately after successful decode | `real_video.input.MP4Input` for local MP4; existing capture loops remain legacy |
| Engine | Decoded pixels, all local inference, vehicle/plate tracking, association, lifetime allocation/closure, quality; separate raw trace persistence | `real_video.engine.Engine` reuses local detector/tracker/quality/HSV; no trace writer |
| Colour | Scalar sample admission, temporal weights and single domain decision | `ColourMetadata.finalize(lifetime, measurements)` → frozen `ColourResult` |
| Plate | Scalar cleanup/parsing, local fusion/eligibility and crop-attempt selection | `PlateMetadata.evaluate(lifetime, transcript)` → waiting or frozen terminal `PlateResult`; reviewed Redis `plate` worker plus opt-in `plate_requests` progressive scalar requests; see current results |
| Manufacturer | Scalar interpretation and domain selection | Unsupported; no model or terminal fact implementation |
| Aggregator | Canonical class consensus, terminal join, immutable natural facts | `Aggregator.join(...)` preserves v0; `join_with_plate(...)` produces v1 through the opt-in Redis `aggregator_plate` role → `JoinResult` |
| Natural construction | Identity, receipt/lifetime checks, DB1 natural schema validation, canonical serialization | `NaturalBuilder.construct(...)` preserves v0; `NaturalPlateBuilder.construct(...)` adds v1; shared `NaturalPolicy` and `core` |
| DB1 consumer | Natural acceptance, key resolution, SQL projection, final fact transaction and receipt | Opt-in `NaturalConsumer` / `RedisDB1Consumer` use shared `RowBuilder.project_natural` and transactional PostgreSQL adapter; native target validation blocked |

`JoinResult` has state `waiting` with no delivery while any enabled branch lacks a terminal result. It never substitutes an omission. Unsupported/disabled branches carry truthful reasons. The existing v0/Redis path supports parent and Colour facts. The explicit v1 path (in memory and opt-in Redis) additionally supports Plate facts or terminal Plate omissions. Each domain owns its selected result; Aggregator delegates authentication to that domain and does not select another winner. Invalid identity/provenance raises a coded `Blocked`; changed accepted payload/provenance raises `PAYLOAD_CONFLICT`.

`UUID5Policy`, `FrozenJSON`, receipt/lifetime/parent checks and natural field construction are shared with RowBuilder. SQL registration records load lazily and are not dependencies of the new pure path. Legacy Colour temporal functions re-export the extracted scalar policy; pixel quality helpers remain in `temporal.py`. Legacy classification imports the extracted canonical `consensus.py` function. No competing policy is introduced.
