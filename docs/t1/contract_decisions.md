## Observation, execution and closure

One event is one **vehicle-track lifetime** in one coordinated run and registered camera. A plate lifetime is not a vehicle lifetime. Events without plates have all three result blocks, with text/category not_attempted when supported but lacking usable input. Independent numeric track IDs must never be joined. Shared vehicle tracking, association and integration are future producer work.

Allocate run_id UUID at coordinated execution start; observation_id UUID at vehicle lifetime creation; message_id UUID once when the complete finalized snapshot closes. UUID wire form is lowercase hyphenated. Rechecks retain observation_id; transport retries retain all three IDs and payload. New execution/reprocessing gets new run and observation IDs. Existing per-service job UUIDs, connection display prefixes and per-attempt sample_id are not substitutes.

Keep zero-based decoded-frame indices per run/camera continuous across reconnects. Track generation starts at 1 per raw ID in that run/camera and increases when its lifetime closes and the ID is reused, including tracker resets. Keep a generation ledger across reconnects; a prefix alone is insufficient. A temporary missed detection within the same retained lifetime does not start a new generation. Reconnect closes old tracks, not merely recognition attempts.

Final reasons: track_lost on the shared tracker's lifetime loss decision; end_of_input on normal EOF; service_stop on explicit stop or configured max_frames/max_seconds limits; camera_outage on failed live receipt/disconnect; tracker_reset on an explicit reset without an outage. Prefer outage as the cause when outage initiates reset. Unexpected file decode failure is operational failure, not normal EOF; quarantine incomplete snapshots until a later failure policy is defined rather than inventing end_of_input. An abrupt crash can leave unpublished observations; recovery/durability remains T3.

At closure, settle permitted in-flight attempts, select outputs, then stamp finalized_at and build a complete immutable message. No crops or recognition attempts is still a valid closed vehicle event. Active UI updates never insert analytical facts. Finalization must run for track loss, normal EOF, stop, outage and explicit reset, using last visible detection's receipt time/frame rather than closure time/frame.

## Time policy

Only host_frame_receipt is allowed in this initial envelope. At each successful decoded-frame receipt, before any inference, capture a paired host UTC instant and host monotonic clock value. A later detected vehicle inherits that frame's receipt pair. Sighting duration is last contributing monotonic receipt minus first, in seconds, including gaps between sightings but excluding post-sighting finalization/recognition time. If first_frame equals last_frame, first_seen and last_seen must represent the same UTC instant, monotonic duration must be zero, and frames_observed must be one. Equivalent UTC fractional spellings represent the same receipt instant. For uploaded video these UTC times describe **replay receipts**, not original capture chronology. Relative media PTS/timebase, source FPS and recording metadata stay separate in diagnostic artifacts/run metrics; never convert relative media time to invented capture UTC. source_capture is deferred to a future version.

Wire UTC uses RFC3339 `YYYY-MM-DDTHH:MM:SS[.ffffff]Z` (0–6 fractional digits). event_at equals finalized_at exactly as a wire string, including fractional spelling. Date dimension uses first_seen's UTC date. first_seen <= last_seen <= finalized_at and run started_at <= first_seen are required in this host-only version; duration need not equal UTC subtraction.

Compare successive paired samples: detect UTC regression or UTC-step notifications, monotonic regression/restart, or a discrepancy `abs(delta_UTC - delta_monotonic)` greater than the proposed 1.0-second tolerance. Log raw pairs, detection cause and configured tolerance; mark affected lifetimes invalid for normal publication and route to operational quarantine. Do not clamp, reorder or reconstruct UTC times from monotonic origin. A closure-time discontinuity also invalidates publication. Recover only after a new stable clock epoch/run; do not emit a fake tracker_reset or inference_error to describe a clock fault. Tolerance/operational recovery policy remains reviewable, and detection cannot certify that an unsignalled smaller step never occurred.

Run duration: host monotonic time from coordinated execution start (before source open) to processing closure after recognition drain, excluding any later annotation replay/export. frames_processed counts each decoded frame actually processed once per camera, summed across cameras, never once per service and never EOF/annotation payloads. FPS = frames_processed/duration_seconds when positive; otherwise null. Totals/end time/output artifacts are mutable completion data outside the finalized envelope.

## States and actual configuration

All five attributes have independent states: plate text, plate category, colour, manufacturer, model.

| State | Required result and interpretation |
|---|---|
| known | Accepted complete text/non-unknown label/non-null model; error null. Confidence may be null. |
| inferred_unknown | Attempt completed without accepted value; null text/model or unknown label, null score/metric/error. |
| not_attempted | Capability exists in this configured producer but is disabled, not ready (e.g. no credential), or had no usable input; unresolved value, null score/metric/error. |
| unsupported | Attribute capability is absent from this integrated/configured producer; unresolved value, null score/metric/error. Code elsewhere is not an integrated capability. |
| inference_error | Attempt failed without usable final result; unresolved value and null score/metric, required bounded error code. |

The envelope records available/enabled/ready for each attribute from **effective producer configuration**, not guessed from filenames. available=false implies enabled=false and ready=false and unsupported. Available but disabled/not-ready implies not_attempted. Available/enabled/ready does not prove an attempt occurred. Configurations/provenance are captured before output publication; readiness flags for these five capabilities are a fixed run snapshot. If capability readiness/configuration changes, start a new run; transient inference/network failures within a ready run are errors, not silent configuration edits. A missing optional agent credential does not negate a functioning local OCR/private-rule/colour capability. Aggregate capability flags describe the active attribute route set; retain per-route configuration in the run's fingerprinted diagnostic configuration artifact.

Earlier transient failures do not override later usable results. An optional colour agent failure does not erase a usable local label. Existing OCR exceptions are swallowed to empty results, and agent unavailable conflates disabled/missing-key/network failure; future producer must collect explicit attempt outcomes. Do not retrofit truthful error states from current UI summaries alone.

## Category and type evidence

Category code exists: [route_plate](../../vehicle/license_plate_service/run_video_pipeline/routing.py) resolves private using valid parser structure, reliable marker/bbox, OCR threshold and compatible digits; its score is min(OCR,marker), not validated category probability. [OpenRouterPlateAgent](../../vehicle/license_plate_service/run_video_pipeline/agent.py) optionally returns private/temporary/diplomatic/military/foreign/other and one joint self-reported score. [process_crop](../../vehicle/license_plate_service/run_video_pipeline/prototype_pipeline.py) copies that joint score into text and category, and supplies a single combined status. Neither branch's accuracy is established by this review. This package enables nothing and does not validate either branch's accuracy. Future admission depends on effective configuration and acceptance/complete-text rules; marker absence alone cannot establish foreign, other or private. Agent category military presently groups police/security and needs taxonomy review.

Require one authoritative type producer for each unified observation. **Proposed authority:** classification consensus operating on the shared vehicle tracker. [aggregate_vehicle_type/update_track_vehicle_type](../../vehicle/vehicle_classification_manufacturer_service/vehicle_classification_manufacturer_service/pipeline.py) uses per-label sums/counts, minimum two observations, deterministic winner and consensus-weighted mean score. It is an evolving aggregate, not a locked type. The alternative [ColourPipeline.process_frame](../../vehicle/vehicle_color_service/vehicle_color_service/detector.py) replaces latest label and detector score together. Its declared lock/vote fields are unused. Both policies are representable; record exact authority. Do not combine separate tracker outputs. Stored type confidence, even though located in colour fact, must support the exact event label/lifetime under that authority. Unknown type gets null score/metric.

No manufacturer/model predictor exists in this checkout's runtime: [VehicleAnalysisService.__init__](../../vehicle/vehicle_classification_manufacturer_service/vehicle_classification_manufacturer_service/service.py) rejects enable_manufacturer, and CLI does not enable it. Their configured states are unsupported with unknown manufacturer/null model and null confidence. Future non-unknown labels/models/metrics require a reviewed manifest revision.

## Counts, sources, scores and latency

One submitted plate-crop recognition operation counts once, including one that fails or never reaches its worker. Whole/left/right OCR calls within it do not increase recognition_attempts; agent HTTP calls/retries are separate counts. agent_retries counts HTTP calls beyond the first call **within each crop attempt**, summed across attempts; it is not simply total_calls-1 when several crops invoke the agent. When calls and retries are both measured, retries cannot exceed calls and positive calls require at least one initial call. When recognition_attempts, agent_api_calls and agent_retries are all measured, `initial_calls = agent_api_calls - agent_retries` is the number of crop attempts that made an initial agent call: require `0 <= initial_calls <= recognition_attempts`, with `initial_calls > 0` when calls are positive. Some submitted crops never invoke the agent. Null means unmeasured, 0 means measured none; do not substitute zero for null or infer an unmeasured counter. Known result necessarily has an attempt; when attempt count is measured it must be >=1. At zero attempts no crop/result/latencies are selected. Known plate text or known category requires selected_crop_frame identifying supporting crop evidence, regardless of confidence or count measurement. Crop quality and confidence may remain null when unmeasured. Failed attempts do not necessarily select a crop. Crop frame/score refers to selected attempted crop, not later best crop. Known agent-sourced text or category requires agent_api_calls >=1 when measured; null remains permitted. This plate HTTP counter does not measure the separate colour agent.

colour_samples is number of retained **local valid frame-level aggregation samples**, even if an agent replaces the selected label. selected_result_source explicitly records local_temporal, agent or none. Invalid/zero-weight observations, discarded samples, detector frames and agent calls are excluded. Preserve local supporting diagnostics when overridden.

local_latency_ms: sum of monotonic elapsed wall durations of whole and any left/right OCR calls on selected crop, each including preprocessing and decoding. Exclude queue, marker detection, parsing/routing, HTTP agent time and other crop attempts. Null if no crop/measurement; not local_total_ms from the current report. total_recognition_latency_ms: monotonic interval from first crop submission to final result resolution at observation closure after permitted attempts settle, including queueing, rechecks, HTTP retries and waits. Null when no attempt/measurement. Finalization stamping/transport/database time is excluded; current per-crop timing.total_ms cannot supply this interval.

All confidence pairs are both null or finite score in [0,1] plus registered named metric. Non-known attributes require null scores. Known does not require a score. Exact source/formula is defined in metrics.v1.json; different metrics must not be averaged. Plate agent score is explicitly joint self-report, not independently measured text/category confidence. Crop quality has its own unbounded nonnegative finite scale, not a probability. Raw prediction scores for unresolved values remain diagnostic only. Manufacturer/model score names remain generic in the structural schema, but application admission requires registered metrics; none are currently registered for these attributes.

Proposed extra fact columns (no new tables): vehicle_type_authority on event; text_source/category_source/normalization_profile/agent_api_calls/agent_retries on plate; selected_result_source on colour. These preserve required provenance within the approved topology and require technical review. Capability flags, versions and immutable run provenance map into dim_pipeline_run.metrics; no surrogate keys are sent on the wire.

Immutable run_context.input_source and model_artifacts[].artifact_ref must contain a non-whitespace character. The same nonempty rule applies to run_context.service_name and model_artifacts[].component; bounded length alone is insufficient. Other wire labels/names/metrics use existing non-whitespace, fixed-enum or identifier-pattern constraints. Optional completion/configuration artifact references documented for future provenance/completion must obey the same nonempty rule when present; they are not added to this envelope. Credential-free references and actual artifact identity still require trusted operational verification.

## Retry equality and ingestion responsibilities

Compare parsed immutable envelope content, including IDs, schema/manifest versions, effective capabilities, immutable run_context, event and all three result blocks. Object order/JSON whitespace are irrelevant; arrays retain order, strings are exact canonical strings, numbers compare as parsed finite numeric values (1 and 1.0 equal). Reject duplicate JSON property names and nonfinite JSON extensions before validation. Stable ID/payload with semantic equality is a no-op; changed payload, reused message_id for another observation, changed message_id for the same v1 observation, or same (run,camera,track,generation) with another observation UUID is a conflict. Cross-event immutable run_context/capabilities for the same run must also agree. Do not regenerate clocks/IDs on retry.

Run output_video, frames_processed, duration_seconds, processing_fps, end UTC and completion diagnostics are excluded by being **absent from this envelope**. They may finalize separately in the existing run dimension. Immutable metrics provenance cannot be silently replaced by mutable completion data. Normalized fact comparison after key resolution uses the same immutable projection; database-generated keys and dimension display metadata are not compared as source payload. Camera metadata is SCD1/current; category/manufacturer meanings are immutable.

Future writer atomically resolves validated labels/keys and inserts one event plus three results, enforcing source tuple uniqueness, at-most-one recognition row per event and composite run/model consistency. Acknowledge after commit. No writer/database behavior is implemented or claimed tested here.
